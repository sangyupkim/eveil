## 3. itch.io 자동 업로드
- 게임 페이지: **https://weak0416.itch.io/eveil** (Draft). GitHub Secrets `BUTLER_API_KEY`, Variables `ITCH_TARGET = weak0416/eveil` 설정 끝. 첫 업로드 성공(사용자가 「잘 뜬다」 확인, 그때는 영문판 전).
- 올리는 법: **사용자가 「itch 올려」라고 할 때만** GitHub → Actions → 「itch 올리기」 Run workflow (`.github/workflows/itch.yml`, 수동 실행). 배포 브랜치(`claude/sludge-…`)를 체크아웃 → test → `tools/build-itch.mjs` → butler push(`--userversion` = GAME_VERSION). 자동으로 바꾸려면 workflow의 push 줄 주석을 푼다.
  - Actions는 GitHub MCP로 실행 기록 · 로그를 볼 수 있다(`actions_list` · `get_job_logs`, owner sangyupkim repo eveil). Run workflow 단추는 사용자가 누른다.
- 묶음 `node tools/build-itch.mjs` → `dist/itch` (gitignore): 파일 1,211 → **559개**, 204MB. itch 제한(파일 1,000 · 500MB · 한 파일 200MB)을 검사하고 넘으면 실패로 끝남(깨진 판을 올리지 않게), 850개 넘으면 주의.
  - 규칙으로 고른다(index.html · css · src · assets · vendor, 관리 화면 · worker · docs · tools 제외) → 새 그림은 저절로 들어간다. 새 게임 폴더를 만들면 `TOP_DIRS` · `PACKS` 확인.
  - 묶음(팩): 효과음(배경음악 제외) · drive trees/props/fx/buildings · flare props/powers/loot → `packs/*.bin` + `packs/index.json`. 게임은 `src/engine2d/packs.js`(window.__PACKS일 때만)로 `image()` · 효과음 `fetchBytes`에서 꺼낸다. `<img>` · CSS로 직접 쓰는 그림은 묶지 않는다.
  - 글꼴: 조각 190여 개를 글꼴마다 하나로 합친 `vendor/fonts/merged/`(`tools/merge_fonts.py`, fonttools). 묶음판 index.html만 이것을 쓴다.
  - 묶음판은 `window.__ITCH` → 서비스 워커 등록 안 함. 서버는 `https://eveil.weak0416.workers.dev/api`(CORS *)로 그대로 — 로그인 캐릭터는 itch에서도 이어진다.
- 시험법: `PORT=5180 node tools/serve.mjs dist/itch` + 다른 주소(5181)의 iframe으로 열기 (스크래치패드 `itchtest.cjs`).
- itch 페이지 재료(영문 소개 · 태그 · 대표 이미지 4종 630×500 · 스크린샷 6장)를 사용자에게 보냄 — 아직 페이지에 넣었는지는 모름. 공개(Public)도 아직.
- 다른 곳 조사: CrazyGames(광고 SDK · 영어 필수 · 용량), 뉴그라운드(수동 업로드 · 투표 심사) — 사용자가 **itch에만 집중**하기로 함.

## 5. 남은 일 · 알려진 것
- **itch에 영문판 올리기**: 사용자가 「itch 올려」라고 하면 Actions 실행을 부탁(또는 안내). 그 뒤 페이지에 글 · 그림 넣고 Public.
- 영문판에서 **화면에 떠야만 보이는 빠진 글**이 더 있을 수 있다(시간 · 이름을 한글로 이어 붙인 문장). 사용자가 보내 주면 `_extra.tsv`에 추가. 이번에 못 열어 본 화면: 던전 결과 창 · 왕좌 원정 · 범람지 · 군세 · 미지의 땅 · 숨은 던전 상자.
- 영어가 길어 넘치는 곳 확인(능력 창 오각형은 STR · DEX … 로 줄임).
- 광산 이름표가 그림과 조금 떨어져 보임(손대지 않음).
- 옛 숙제: G4 마을 건물 부딪힘 범위 점검, H1 일일 퀘스트 각성 맞춤 · 생산 · 주간.

## 6. 영문판 구조 (v0.51.0)
- **코드의 한글은 그대로**, 화면에 나가는 순간 번역한다. 데이터 이름도 바꾸지 않는다(코드가 「단검」 같은 한글 이름으로 비교하는 곳이 있다).
  - `src/i18n/index.js`: `initLang()`(main.js boot 처음) — 영어면 `en.js`를 받고, DOM은 MutationObserver로 글자 · title · placeholder · alt를, 캔버스는 `fillText` · `strokeText` · `measureText`를 감싸 번역. `data-noi18n`이 붙은 곳은 건너뜀(언어 단추).
  - 열쇠 `src/i18n/key.js tkey`: 한글이 아닌 덩어리(숫자 · 영문 · 이름) 하나를 `{}`로. 값은 `fill`({} 차례 · {0} 번호).
  - `tr()` 순서: 그대로 찾기 → 앞뒤 빈칸 · 가운뎃점 · ◆ 같은 기호 떼기 → `​`로 일부러 나눈 자리(칭호 특성 「조건​ 효과」) → 「 · 」 조각마다 → **이름(짧은 표 항목)을 긴 것부터 하나씩 영어로**(앞뒤에 `⁠` 경계를 넣어 옆 숫자와 한 자리로 묶이지 않게, 낱말 경계 · 조사 확인, 한 글자 약자는 제외) → 이름 조각/나머지 조각 → 줄 · 「 — 」 등으로 나눠서 → 짧은 이름(1 ~ 6자)은 로마자(`romanize`, 용병 이름 · 한글 닉네임) → 그래도 없으면 한글 그대로 + `__i18nMissing`에 기록.
  - 언어: localStorage `eveil-lang`. 처음이면 기기에 예전 저장(`ashen-last` · `ashen-account` · `ashen-save*` · `ashen-chars`)이 있으면 한국어, 없으면 영어. 첫 화면 오른쪽 위 `#langPick`(data-setlang) · 설정 「언어」(data-setlang2) → 저장 후 새로고침.
  - 영문판 전용 조정: 능력 창 오각형 STR · DEX · INT · WIS · VIT, 스킬 창 「숙련」 → 「숙련도」(Mastery).
- **번역표 만들기**
  - `node tools/i18n-extract.mjs` (acorn, `npm i` 필요): src 모든 문자열 · 템플릿(`${}` → {}) · index.html에서 한글 조각을 뽑아 `tools/i18n/keys.json` · `todo.json`(번역 없는 것, 파일별). 금지어 목록(nickrules)은 뺀다. 남은 35개는 용병 이름 한 글자 조각(로마자로 처리).
  - 파일별 묶음: `node tools/i18n-batch.mjs <파일> <이름>` → `tools/i18n/batch/<이름>.json`, 번역은 `tools/i18n/parts/<이름>.tsv`(「번호<TAB>영어」). **이름이 겹치면 덮어쓰니 주의**(한 번 skills가 덮였었다).
  - 손으로 더하기: `tools/i18n/parts/_extra.tsv`(「한글 틀<TAB>영어」) — 맨 나중에 합쳐 이긴다. 화면에서 모은 빠진 글은 여기에.
  - `node tools/i18n-merge.mjs` → `src/i18n/en.js`(약 3,850줄).
- **확인**: 스크래치패드 `en.cjs <tag> 1`(창 40여 곳 · 가이드 전 장 · 건물 9종 탭 · NPC 열고 빠진 글을 `en_missing_<tag>.txt`로), `en2.cjs`(아이템 · 스킬 넣고 가방 · 스킬 · 대장간 등), `trdbg.cjs '문장' …`(한 줄 번역 시험), `kocheck.cjs`(예전 저장이 있으면 한국어인지).
- 번역 글 바꾸기 예: 「강화」 = Enhance(던전 난이도도 같은 글), 「단계」 = Tier, 「{}단계」 = Lv.{}, 「숙련」 = Skilled(용병 등급).
