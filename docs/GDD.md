# 가제: 에베이 (Ashen Chronicle) — 기획서 v0.2

> 어두운 판타지 세계의 **쿼터뷰 액션 RPG**.
> 레벨이 없다. **내가 한 행동이 곧 내 성장**이 된다.
> 검을 휘두르면 힘이, 주문을 외우면 지능이, 많이 맞으면 체력이 오른다.
> 스킬은 사서 배우지 않고 **사냥으로 주운 스킬북**으로 익히며, 쓸수록 강해진다.

## 0. 실현 가능성 검토 (결론 먼저)

### 0.1 요약

| 요구 사항 | 웹 구현 가능 여부 | 비고 |
|---|---|---|
| 쿼터뷰 시점, 판타지, 어두운 분위기 | **가능** | Three.js(WebGL) 3D + 고정 쿼터뷰 카메라 + 안개/조명/후처리로 연출 |
| 디아2·리니지 / 첨부 이미지와 흡사한 그래픽 | **부분 가능** | 시스템·연출은 가능. **아트 에셋 품질이 최대 변수** (0.3 참고) |
| 레벨 없는 행동 기반 스탯 성장 | **가능** | 순수 로직. 난이도 낮음, 밸런스 설계가 핵심 |
| 사용 숙련도로 강해지는 스킬 | **가능** | 순수 로직 |
| 몬스터 등급별 스킬북 드랍 | **가능** | 데이터(JSON) 드랍 테이블 |
| 기본 장비만 판매, 나머지는 드랍 | **가능** | 디아블로식 등급·랜덤 옵션 아이템 |
| 자동 사냥 (이미지의 "자동 사냥 중") | **가능** | 간단한 AI 상태 기계 |
| PC + 모바일 (가상 조이스틱) | **가능** | 이미지 레이아웃 그대로 구성 가능 |
| 리니지 같은 **다중 접속(MMO)** | **가능하지만 별도 대형 작업** | 서버·DB·동기화 필요. 1차는 싱글 플레이 권장 (0.4) |

**결론: 기획 방향 자체는 웹게임으로 충분히 구현 가능하다.**
게임 시스템(성장·스킬·드랍·장비·전투)은 전부 제가 직접 구현할 수 있는 범위다.
다만 "첨부 이미지 수준의 그래픽"은 코드가 아니라 **3D 모델·텍스처·애니메이션 에셋**에 달려 있으므로, 아래 방식으로 접근한다.

### 0.2 그래픽 구현 방식 비교

| 방식 | 장점 | 단점 | 이미지와의 유사도 |
|---|---|---|---|
| **A. Three.js 3D + 고정 쿼터뷰 (권장)** | 첨부 이미지(3D 모바일 MMO)와 같은 구조. 조명·그림자·안개로 어두운 분위기 연출 쉬움. 무료(CC0) 3D 에셋 풍부 | 에셋 스타일 통일이 과제. 모바일 성능 관리 필요 | 높음 |
| B. 2D 아이소메트릭 스프라이트 (Phaser/PixiJS) | 디아블로2 감성. 가벼움 | 8방향 애니메이션 스프라이트를 구하기 어렵고, 무료 에셋이 적음 | 중간 (디아2 쪽에 가까움) |

→ **A안 권장.** 첨부 이미지는 실제로 3D 엔진으로 만든 화면이며, 같은 구조를 웹에서 재현하는 것이 가장 가깝다.

### 0.3 아트 에셋 — 가장 큰 리스크

- 저는 코드로 지형·조명·이펙트·UI는 만들 수 있지만, **상용 MMO 수준의 캐릭터 모델·애니메이션을 직접 그려낼 수는 없다.**
- 1차 해결책: **CC0(상업 이용·수정 자유) 무료 에셋**
  - 캐릭터/몬스터/던전: KayKit(Adventurers, Skeletons, Dungeon), Quaternius(몬스터·판타지 팩)
  - 지형 텍스처: Poly Haven, ambientCG (풀·흙·돌 PBR 텍스처)
  - 효과음: Kenney, freesound(CC0 한정)
- 이 에셋들은 **약간 로우폴리/스타일라이즈드** 계열이다. 실사풍인 이미지와 100% 같지는 않지만,
  어두운 색보정·안개·비네팅·부드러운 그림자를 입히면 "어둡고 묵직한 쿼터뷰 RPG" 분위기는 충분히 낼 수 있다.
- 2차(선택): 유료 에셋팩 구매 또는 직접 제작한 모델로 교체. **코드는 에셋 교체만으로 바뀌도록** 데이터 주도로 설계한다.

### 0.4 싱글 vs 온라인

- 리니지식 다중 접속은 서버(Node.js), DB, 실시간 동기화, 치트 방지가 필요해 **규모가 몇 배**가 된다.
- 권장: **1차는 싱글 플레이(브라우저 저장)** 로 핵심 재미(행동 성장·스킬북·파밍)를 검증.
  게임 로직을 렌더링과 분리해 두어, 나중에 로직을 서버로 옮길 수 있게 만든다.

## 1. 게임 개요

| 항목 | 내용 |
|---|---|
| 장르 | 쿼터뷰 액션 RPG / 핵앤슬래시 파밍 |
| 배경 | 어두운 중세 판타지 (몰락한 왕국, 역병, 망자) |
| 플랫폼 | 웹 브라우저 (PC + 모바일), PWA 설치 지원 |
| 시점 | 고정 쿼터뷰 (약 50~55° 내려다봄), 줌 인/아웃만 허용 |
| 조작 | PC: 클릭 이동 + 단축키 스킬 / 모바일: 가상 조이스틱 + 스킬 버튼 |
| 핵심 판타지 | "레벨이 아니라 **내가 싸운 방식**이 나를 만든다" |

### 1.1 디자인 원칙
1. **레벨은 없다.** 화면에 레벨 숫자를 띄우지 않는다. 강함은 스탯·스킬 숙련·장비로만 드러난다.
2. **행동 = 성장.** 플레이어가 한 행동은 반드시 어떤 스탯으로 돌아온다. 결과를 플레이어가 납득할 수 있게 보여 준다.
3. **모든 힘은 필드에서.** 스킬과 좋은 장비는 상점에 없다. 사냥터가 곧 상점이다.
4. **강한 적 = 강한 보상.** 위험을 감수한 만큼 좋은 스킬북과 장비가 나온다.
5. **데이터 주도.** 몬스터·스킬·아이템·드랍표는 전부 JSON. 코드 수정 없이 콘텐츠 추가.

## 2. 코어 루프

```
마을 (기본 장비 구매 · 물약 · 창고 · 잡화)
   ↓
사냥터 진입 → 몬스터 사냥 (수동 / 자동 사냥)
   ↓                       ↘
경험치(EXP) 획득           행동 기록 누적 (휘두름·시전·피격·회피 …)
   ↓                       ↙
EXP가 기준치에 도달 → [각성] 행동 기록 비율대로 스탯 상승
   ↓
스킬 사용 → 스킬 숙련 EXP → 스킬 랭크 상승
   ↓
드랍: 골드 · 장비(등급·랜덤 옵션) · 스킬북(몬스터 등급 비례)
   ↓
더 강한 사냥터 / 정예 · 네임드 · 보스 도전
```

## 3. 성장 시스템 — 행동 기반 스탯 ("각성")

### 3.1 스탯

| 스탯 | 효과 | 주로 오르는 행동 |
|---|---|---|
| **힘 (STR)** | 근접 피해, 무거운 장비 착용 조건, 막기 | 근접 무기로 공격·적중, 방패 막기 |
| **민첩 (DEX)** | 원거리 피해, 공격 속도, 치명타율, 회피율 | 활·투척 적중, 치명타, 회피 성공, 이동하며 싸우기 |
| **지능 (INT)** | 주문 피해, 최대 마나 | 공격 주문 시전·적중 |
| **정신 (WIS)** | 마나 회복, 회복·보조 주문 효과, 상태이상 저항 | 회복/버프 주문, 마나 소모, 상태이상에서 버티기 |
| **체력 (VIT)** | 최대 HP, HP 회복, 방어 | 피해를 받음, 낮은 HP에서 생존 |

> 시작 스탯: 모두 10. 직업 선택 없음(무직업). 플레이 방식이 곧 직업이 된다.

### 3.2 동작 방식

1. 전투 중 행동마다 해당 스탯의 **행동 포인트(AP)** 가 쌓인다. (플레이어에게는 "성향 게이지"로 표시)
2. 몬스터를 처치하면 **EXP** 를 얻는다. EXP 바는 이미지처럼 화면 하단에 % 로 표시.
3. EXP가 100%가 되면 **각성**이 일어난다.
   - 각성 1회당 **스탯 포인트 P점**이 자동 분배된다 (기본 P = 5).
   - 분배는 그동안 쌓인 **AP 비율**을 따른다.
   - 각성 후 AP 기록은 **절반으로 감소** (최근 플레이 방식이 더 크게 반영되되, 갑작스런 전환도 완만하게).
4. 다음 각성까지 필요한 EXP는 점점 늘어난다. `필요 EXP(n) = 100 × 1.15ⁿ` (n = 누적 각성 횟수, 밸런스 시 조정)

### 3.3 행동 → AP 표 (초안)

| 행동 | AP |
|---|---|
| 근접 공격 적중 1회 | 힘 +1.0, 민첩 +0.2 |
| 근접 처치 | 힘 +2.0 |
| 원거리 적중 1회 | 민첩 +1.0, 힘 +0.2 |
| 치명타 발생 | 민첩 +0.5 |
| 회피 성공 | 민첩 +0.8 |
| 공격 주문 적중 | 지능 + (소모 마나 ÷ 5) |
| 회복·버프 주문 시전 | 정신 + (소모 마나 ÷ 5) |
| 마나 소모 총량 100당 | 정신 +1.0 |
| 피해를 받음 | 체력 + (받은 피해 ÷ 최대 HP × 10) |
| HP 30% 이하에서 처치 | 체력 +1.5 |
| 방패로 막기 | 체력 +0.5, 힘 +0.3 |

### 3.4 분배 공식

```
각 스탯 몫 = P × (해당 AP ÷ 전체 AP)
→ 정수 부분 먼저 지급, 남은 포인트는 소수점이 큰 순으로 지급 (동률은 무작위)
```

**예시** (P = 5)

| 플레이 | AP 비율 | 결과 |
|---|---|---|
| 검만 휘두르며 사냥 | 힘 70% · 체력 20% · 민첩 10% | 힘 +4, 체력 +1 |
| 마법 위주, 거의 안 맞음 | 지능 75% · 정신 25% | 지능 +4, 정신 +1 |
| 검 + 마법 섞어서, 많이 맞음 | 힘 30% · 지능 30% · 체력 40% | 체력 +2, 힘 +2, 지능 +1 (나머지 동률 무작위) |

→ 기획 의도대로 "**한 스탯이 많이 오를 수도, 여러 스탯이 골고루 오를 수도**" 있다.

### 3.5 어뷰징 방지

| 문제 | 대책 |
|---|---|
| 약한 몹에게 일부러 맞아 체력만 올리기 | AP는 **EXP를 주는 적**과의 전투에서만 쌓임. 너무 약한 적(내 강함 대비)은 AP 0 |
| 허공에 주문 난사 | 공격 주문 AP는 **적중 시에만** 지급 |
| 한 스탯 무한 올리기 | 스탯이 높을수록 같은 행동의 AP 효율 감소 (소프트캡) |
| 자동 사냥 방치 | 자동 사냥도 성장은 되나, AP·드랍률 일부 감소(예: 80%) — 결정 필요 |

### 3.6 숨은 성장 지표

레벨은 보이지 않지만, 몬스터 난이도·드랍 기준을 위해 내부적으로 **"총 스탯 합"** 을 강함 지표로 사용한다.
사냥터 입구에 "권장 전투력"만 보여 준다.

## 4. 스킬 시스템

### 4.1 획득 — 스킬북 드랍 전용

- 상점에서 스킬을 팔지 않는다. **오직 몬스터 드랍 스킬북**으로만 배운다.
- 스킬북을 사용하면 스킬을 영구 습득. 이미 아는 스킬의 책은 **숙련 EXP로 흡수** 하거나 팔 수 있다.
- 습득에는 **스탯 조건**이 있다 (예: 화염구 = 지능 20). 조건이 안 되면 들고 있다가 나중에 배운다.

### 4.2 스킬북 등급과 드랍

| 스킬북 등급 | 예시 스킬 | 주로 드랍하는 몬스터 |
|---|---|---|
| 하급 | 강타, 화염 화살, 응급 처치 | 일반 몬스터 |
| 중급 | 회전 베기, 화염구, 치유의 빛 | 정예 몬스터 |
| 상급 | 대지 가르기, 연쇄 번개, 신성 보호막 | 네임드 몬스터 |
| 고대 | 망자 소환, 운석 낙하 | 지역 보스 |
| 전설 | 고유 스킬 (각 보스 1종) | 최종·히든 보스 |

| 몬스터 등급 | 스킬북 드랍률 (초안) | 나올 수 있는 등급 |
|---|---|---|
| 일반 | 0.3% | 하급 |
| 정예 (이름이 파란색) | 3% | 하급~중급 |
| 네임드 (이름이 노란색) | 15% | 중급~상급 |
| 보스 | 100% (1권 확정) | 상급~고대, 낮은 확률로 전설 |

### 4.3 스킬 강화 — 사용 숙련도

- 스킬마다 **랭크 1~10**. 스킬을 쓸 때마다 **숙련 EXP**가 오른다.
  - 사용 시 +1, 적에게 적중 시 +1, 처치 시 +2 (보조 스킬은 효과 발동 시)
  - 강한 적에게 쓸수록 숙련 EXP 배율 ↑
- 랭크가 오르면 피해·범위·쿨타임·마나 효율이 강해진다.
- **랭크 5, 10에서 변화(분기)**: 예) 화염구 랭크 5 → "폭발 범위 증가" 또는 "화상 지속" 중 택1.
- 스킬 숙련은 각성(스탯)과 **별개 시스템**. 같은 화염구를 써도 스킬 숙련 + 지능 AP가 동시에 쌓인다.

### 4.4 스킬 장착

- 퀵슬롯 최대 6~8칸 (첨부 이미지 하단 슬롯 구성). 배운 스킬 중 골라 장착.
- 무기 종류 제한 없음. 단, 무기 계열이 맞으면 보너스 (예: 검 스킬 + 검 장착 시 피해 +20%).

## 5. 장비 · 아이템

### 5.1 획득

- 상점: **기본 장비(일반 등급)와 소모품만** 판매.
- 그 외 모든 장비는 **사냥 드랍**. 몬스터가 강할수록 높은 등급·높은 아이템 레벨.

### 5.2 등급

| 등급 | 색 | 랜덤 옵션 수 | 획득처 |
|---|---|---|---|
| 일반 | 흰색 | 0 | 상점, 드랍 |
| 마법 | 파랑 | 1~2 | 드랍 |
| 희귀 | 노랑 | 3~4 | 드랍 |
| 영웅 | 주황 | 고정 고유 옵션 + 2 | 네임드·보스 |
| 전설 | 초록(세트)/금색 | 고유 효과 | 보스 |

- 랜덤 옵션 예: 힘 +3, 공격 속도 +8%, 화염 피해 +12, 최대 HP +40, 받는 피해 -5%, 스킬 숙련 획득 +10%
- 착용 조건은 **스탯**으로 (예: 판금 갑옷 = 힘 30). 레벨 조건 없음.

### 5.3 장비 슬롯

무기 · 보조(방패/오브/화살통) · 투구 · 갑옷 · 장갑 · 신발 · 허리띠 · 목걸이 · 반지 ×2

### 5.4 기타

- 인벤토리: 칸 수 제한 (확장 가능). 창고: 마을.
- 골드 획득처: 드랍, 아이템 판매. 사용처: 기본 장비, 물약, 수리(선택), 창고 확장.

## 6. 전투

- 실시간 액션. 기본 공격 + 퀵슬롯 스킬.
- PC: 땅 클릭 이동 / 몬스터 클릭 공격 (디아블로식), 숫자키 스킬.
- 모바일: 왼쪽 가상 조이스틱 이동, 오른쪽 기본 공격 + 스킬 버튼 (첨부 이미지 배치).
- **자동 사냥**: 주변 몬스터 탐색 → 접근 → 장착 스킬 순서대로 사용 → HP 낮으면 물약.
- 피해 표시: 떠오르는 숫자, 치명타는 큰 글씨 (이미지의 "CRITICAL").
- 몬스터 이름 색으로 등급 구분 (일반 흰색 / 정예 파랑 / 네임드 노랑 / 보스 빨강).

## 7. 세계 · 지역 (초안)

몰락한 왕국 **아셴바르**. 역병과 망자의 기운이 번진 땅을 되찾는다.

| 지역 | 분위기 | 주요 몬스터 | 보스 |
|---|---|---|---|
| 마을: 여명 초소 | 횃불, 목책, 안개 | — | — |
| 1. 푸리에 들판 | 해질녘 초원 (첨부 이미지 느낌) | 고블린, 들개, 늑대 | 고블린 족장 |
| 2. 썩은 숲 | 짙은 안개, 뒤틀린 나무 | 거미, 숲 망령, 버섯 괴물 | 거미 여왕 |
| 3. 버려진 광산 | 어두운 갱도, 횃불 조명 | 코볼트, 골렘, 박쥐 | 광부의 원혼 |
| 4. 망자의 묘지 | 달빛, 무덤, 녹색 안개 | 스켈레톤, 구울, 레이스 | 묘지기 리치 |
| 5. 무너진 성채 | 불타는 성, 붉은 하늘 | 타락한 기사, 악마 | 타락한 왕 |

- 각 지역 안에 정예 무리·네임드가 일정 시간마다 출현.
- 지역이 깊어질수록 드랍 아이템 레벨·스킬북 등급 상승.

## 9. 기술 설계

| 항목 | 선택 |
|---|---|
| 렌더링 | **Three.js** (WebGL) — 3D 지형·모델·그림자·안개·후처리 |
| 언어/빌드 | JavaScript(ES Modules) + Vite (개발 서버·번들) |
| UI | HTML/CSS 오버레이 (HUD, 인벤토리, 창) |
| 데이터 | `data/*.json` — 몬스터, 스킬, 스킬북, 아이템, 옵션, 드랍표, 지역 |
| 저장 | IndexedDB(또는 localStorage) 자동 저장 |
| 배포 | GitHub Pages (정적 웹) + PWA |
| 구조 | **게임 로직(시뮬레이션)과 렌더링 분리** → 테스트·밸런스 시뮬레이터·향후 서버화 대비 |

### 9.1 폴더 구조 (예정)

```
src/
  engine/   렌더러, 카메라, 입력, 에셋 로더
  game/     전투, 성장(각성), 스킬 숙련, 드랍, 아이템 생성, AI, 자동사냥
  ui/       HUD, 창(인벤·스킬·캐릭터), 팝업
  data/     JSON 로더/검증
assets/     모델(glTF), 텍스처, 사운드 (라이선스 목록 포함)
data/       게임 콘텐츠 JSON
tools/      데이터 검증, 성장·드랍 밸런스 시뮬레이터
docs/       기획서
```

### 9.2 성능 목표

- PC 60fps, 중급 모바일 30fps 이상.
- 화면 내 몬스터 최대 30~40, 인스턴싱·LOD·그림자 범위 제한으로 관리.
