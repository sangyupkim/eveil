> 새 세션은 이 문서를 먼저 읽는다. 마지막 정리: **2026-11-12, 게임 버전 0.20.0** (커밋 `414f052` 기준).
> 예전(3D · KayKit 시절) 기록은 git 기록에만 남기고 이 문서에서는 뺐다 — 지금 코드와 맞지 않는다.

## 0. 한눈에

- **무엇:** 어두운 판타지 쿼터뷰(아이소메트릭) 2D 웹 액션 RPG. 디아블로풍. 레벨 대신 **각성**(행동한 방식대로 스탯이 오름), 스킬북으로 배우고 쓸수록 오르는 스킬, 드랍 장비 · 강화 · 보석, 베이스캠프(마을) 경영, 용병.
- **그림:** Flare: Empyrean Campaign 2D 그림(CC-BY-SA 3.0) + flare-mod-noname 몬스터 + Quaternius 펫(CC0). 3D 엔진 없음(three는 수학용으로만).
- **빌드 없음:** 정적 사이트(ES 모듈 그대로). GitHub Pages로 배포.
- **서버:** 로그인 · 서버 저장 · 순위는 **다른 저장소 `sangyupkim/eonrift`의 Cloudflare Worker `worker/ashen.ts`** (eonrift `dev` 브랜치 = 테스트 서버 `https://dev-eonrift.weak0416.workers.dev/api`).
- **사용자와는 한국어로 대화.** 응답 · 패치노트 · 코드 주석 모두 한국어.

## 2. 실행 · 점검

- 개발 서버: `node tools/serve.mjs` (= `npm start`) → http://localhost:5173. 컨테이너가 바뀌면 꺼져 있다 (`ERR_CONNECTION_REFUSED`면 `setsid nohup node tools/serve.mjs >/dev/null 2>&1 &`로 다시 켬).
- 테스트: `npm test` (= `node tools/test.mjs`) — **19개 통과 상태**. 각성 · 스킬 · 드랍 · 사망 · 장착 · 퀘스트 · 마을(짓기 · 생산 · 강화 · 용병) · 던전 등.
- 경제 시뮬: `node tools/sim/economy.mjs` (돌아가기만 하면 됨, 마을 · 용병 함수를 바꾸면 같이 고친다).
- 화면 확인: Playwright(설치돼 있음, `require('playwright')`). 스크립트와 스크린샷은 **세션 스크래치패드에** 두고 경로를 절대 경로로 쓸 것 — 상대 경로로 찍었다가 스크린샷이 저장소에 커밋된 적이 있다(`town2.png` 등, 지웠음).
  - 게임에 들어가기: 제목 화면 `#btnPlay`(캐릭터 선택 후) 또는 `#btnNewChar` → `#btnNew`, 첫 무기 `[data-start]` → `#btnStartPick`.
  - 개발용 전역: `window.__game = { world, stage, st, save, tut, windows }`, `window.__stop`(화면 멈춤), `window.__noSave`(저장 끔), `window.__fps`.
  - 휴대폰 기준 크기 844×390(가로), 세로 회전 확인은 `devices['iPhone 13']`.
- 이 작업 환경에서는 **dev-eonrift 주소가 DNS로 안 풀린다** (네트워크 정책). 서버가 얽힌 기능은 `worker/ashen.ts`를 Node 22의 `node:sqlite` + `--experimental-strip-types`로 D1 흉내를 내 돌리고, Playwright `context.route('https://dev-eonrift.weak0416.workers.dev/**', ...)`로 게임 요청을 그 함수로 넘겨 브라우저 여러 개로 시험했다 (아래 9장 참고).

## 4. 게임 규칙 요점 (지금 상태)

### 성장
- 레벨 없음 → **각성**(`st.awakenings`). 경험치가 차면 각성, 행동 비율대로 스탯 5종(힘 · 민첩 · 지능 · 정신 · 체력) 분배. 칭호 20/40/60.
- 시작 무기 셋(검 · 활 · 지팡이) 중 하나 고르기 → 그 계열 스킬북을 바로 준다. **튜토리얼은 사용자 요청으로 없앴다** (`tutorial.js`에서 `st.tut = 99`, `st.guide = 99`; 코치 안내도 끔). 대신 메뉴 탭 **가이드북**.

### 세상
- **접속할 때마다 새 맵** (v0.16): `startGame`에서 매번 `st.worldSeed`를 새로 뽑고 안개 · 바닥 아이템을 지우고 마을(0,4)에서 시작. 야영지 투자(`st.camps`)는 지역 id별로 남는다.
- 지역 12곳(레벨 1~66), 지역 사이 황야 · 호수 · 언덕, 지역마다 야영지(포탈 · 안전지대), 던전(미로 · 방 · 동굴, `data/dungeons.js`).
- 세계 단계 평온 · 악몽 · 지옥(`TIER_NAMES`, +66레벨씩).
- 마을(베이스캠프) 반지름 `TOWN.r = 30` (v0.19에서 24→30). 가장 가까운 지역 가장자리와 몇 칸 여유뿐이니 더 키우려면 지역 거리(`generateWorld`의 ×1.55)도 함께 본다.

### 장비 · 드랍 · 강화
- 레벨 제한 200까지 종류별 장비(70~200은 11단계 `HIGH_TIERS`, `h${lv}_${종류}`, 상점 판매 없음).
- 드랍 확률(`data/config.js` `LOOT`): 일반 1% · 정예 8% · 네임드 25% · 보스 40%(1~2개). **보스도 확률로만.** 강한 몬스터일수록 좋은 등급. 전설 `NAMED_CHANCE` 보스 6% · 네임드 1.5% · 던전 8%.
- 보석 10등급(`GEM_GRADES`, 몬스터 레벨로 등급 결정 `gemGradeFor`). 상점은 낮은 등급만.
- **강화** (`data/buildings.js` `ENHANCE`, `game/town.js` `enhance`): +1~+10, 대장간 단계가 상한. 확률 `[1,1,.9,.7,.5,.35,.25,.15,.1,.05]` (+5가 50%, +10이 5%). 실패해도 단계 유지.
  - **장인의 기운(장기백):** 실패마다 `그 시도 확률 × 0.465` 적립, 100%면 다음은 반드시 성공. 실패마다 기본 확률의 10%씩 확률 상승(최대 2배). 장비에 `it.jang` · `it.fails`. 평균 +9→+10 약 11회, 최악 26회.
  - **계획:** 나중에 +20까지 늘리고 높은 단계는 장비 파괴를 넣는다 (사용자 말). 아직 안 함.
- 재련(가장 약한 옵션 다시 굴림) · 분해 · 일괄 판매.

### 능력치 파편 (v0.21, `game/shards.js`)
- 장비를 갈아 끼우면(`inventory.equip`) 빠진 장비에서 `SHARD.swapChance`(6%) 확률로 그 장비 옵션 하나가 파편(`{ base: 'shard', shard: { id, v } }`)으로. 보스 장비 드랍 하나가 `bossChance`(12%)로 파편으로 바뀜(`rollShard`, 희귀 세기). 기본 피해 · 방어력은 옵션이 아니라 나오지 않는다.
- 대장간 화면 「능력치 파편」(`windows.shardPanel`): 파편 · 착용 장비를 고르고 옵션 잠금 → `applyShard`가 잠그지 않은 옵션 하나를 무작위로 바꿈(같은 옵션이 있으면 그것을 바꿈, 부위에 못 붙는 옵션은 막음). 잠금 수 `lockMax` = 대장간 3단계 1 · 4단계 2 · 5단계 3. 비용 `shardCost`(금화 · 강화석).

### 퀘스트
- 48개, 경비대장 하겐에게 보고. **가방이 가득하면 보상 받기를 막고 창 위 알림**(「가방 N칸이 필요합니다」, `questTurnIn` → `bagFull`). 바닥에 떨어뜨리지 않는다(사용자가 그렇게 원함).

### 마을 · 용병 (v0.17~0.19)
- 집터 7곳 `PLOTS` (반지름 20 고리, 북쪽부터 시계 방향). 건물 7종과 **각성 해금** `need`:
  | 건물 | 해금 | 역할 | 일하는 용병 솜씨 · 효과 (`BONUS`) |
  |---|---|---|---|
  | 대장간 | 0 | 강화 · 재련 · 분해 | 손재주 · 강화 금화 -5%/10솜씨 (최대 30%) |
  | 약초밭 | 0 | 물약 생산 | 재배 · 생산 |
  | 숙소 | 3 | **고용 한도** = 1 + 침대 `[0,3,5,7,10,14][lv]` | 살림(`care`, v0.21) · 체력 소모 -15% (최대 60%) |
  | 여관 | 3 | 매 시간 용병이 찾아옴 · 파견 | 탐험 · 휴식 회복 +20% (최대 100%) |
  | 광산 | 6 | 강화석 생산 | 채광 · 생산 |
  | 제작소 | 10 | 세트 장비 제작 | 손재주 · 제작 금화 -5% (최대 30%) |
  | 연구소 | 15 | 영구 연구 | 학식 · 연구 시간 -8% (최대 50%) |
- 용병(`game/town.js`): 여관에 **매 시간** `2 + 여관 단계`명이 찾아옴(`recruits`, 시간 키 `t.rec.hr`). 등급 평범 · 숙련 · 정예 · 전설, 솜씨 5종(채광 · 재배 · 손재주 · 학식 · 탐험) 중 하나가 뛰어남, 얼굴 `m.face`, 체력 `m.sta`/`staMax`.
  - 일 맡기기 `assignMerc(st, id, plot)` (건물 단계만큼 자리). 일하면 시간당 체력 8 소모 · 솜씨 · 경험 상승, 0이면 `tired`로 다 찰 때까지 쉼(시간당 12 회복). 꺼 둔 시간도 `tick`이 15분씩 나눠 계산(최대 72시간).
  - 레벨 20에서 각성(최대 10, 금화 `awakenCost`), 솜씨 +15% · 상한 상승.
  - 파견(`dispatch`): 해방한 지역만, 체력 12/35/70, **사망 확률** `deathChance`(약할수록 · 길수록 높음, 최대 50%). 죽으면 목록에서 사라짐.
  - 예전 저장의 `t.workers`(일꾼 수)는 솜씨 10 용병으로 바뀜(`migrateMercs`).
- 건물 그림(`world.js` `refreshTown` 안 `LOOK`): 대장간 · 여관 = 돌오두막(grassland 296, 색 필터로 구분), 광산 = 땅속 계단(dungeon 286), 연구소 = 마법진(ruins 380) + 돌기둥 · 석상, 제작소 · 숙소 = **통나무집**.
  - **통나무집은 세로 띠 4장을 이어 붙인 그림**이다. 이음매 색을 계산해 찾은 자리(px 기준점): A(창문) `208(0,0) 209(96,48) 210(192,0) 211(288,-48)`, B(문) `212(0,0) 213(96,48) 214(192,96) 215(288,48)`. 세계 좌표 = px/64, py/32. 짐작으로 붙이면 잘려 보인다(사용자가 두 번 지적).
  - 울타리는 사용자 요청으로 없앴다(마을 · 약초밭). `world.waypoint`도 그대로 목적지를 돌려준다.
  - 일하는 용병은 주인공 겹그림 + 연장(광산 · 대장간 · 제작소 손도끼, 약초밭 단검=낫 대용, 연구소 지팡이)으로 건물 옆에서 `swing`/`cast`를 되풀이.

### 캐릭터 · 계정 (v0.19.1~0.20)
- **캐릭터 여럿**(`game/chars.js`): 기기 저장 `ashen-chars`(cid 목록) + `ashen-save-<cid>`, 마지막 캐릭터 `ashen-last`. 최대 6. 예전 단일 저장 `ashen-save`는 첫 실행 때 첫 캐릭터로 옮김.
- 제목 화면: 캐릭터 카드(기기 + 서버 목록 합침) · 게임 시작 · 새 캐릭터 · 삭제 · 계정(로그인 · 가입).
- **닉네임:** `st.nick`(정하면 `st.name`도 같게). 규칙 한글 · 영문 · 숫자 · _ 2~10자(`NICK_RE`, 서버와 같음). 없으면 첫 무기 고른 뒤 닉네임 창. 로그인 상태면 서버에 차지(`ash_nick`), **대소문자 무시 중복 불가**. 비로그인 때 정한 닉네임은 나중에 로그인하면 차지 시도(`st.nickOk`), 겹치면 다시 묻는다. 메뉴에서 바꾸기.
- 메뉴: **메인 화면으로**(저장 후 새로고침) · 캐릭터 삭제(이 캐릭터만, 기기 + 서버).
- **한 계정 = 지금 하는 기기 하나:** 게임 시작 때 `cloud.claim(cid)` → 서버가 이 토큰을 `ash_active`에 등록하고 그 캐릭터 최신 저장을 돌려줌(더 새 것이면 그것으로 시작). 다른 기기가 claim하면 옛 기기의 저장은 서버가 `moved`로 거절, 옛 기기는 15초마다 `ash_ping`으로 알아채 **게임을 멈추고 「다른 기기에서 접속했습니다」** 창, 기기 저장은 `savedAt = 0`(낡음)으로 표시. 서버 저장 간격 20초(`GAP`).
- 순위: 서버 `ash_rank`, **닉네임을 차지한 캐릭터만**, 이름은 닉네임.

### 조작 · UI
- 공격 버튼은 근처(4칸) NPC · 건물 터가 있으면 **상호작용 버튼**(파란색 + 대상 이름)으로 바뀜 (`input.js` `interactTarget`).
- PC 단축키 지정: 메뉴 → 단축키 지정 (`data/keys.js`, `st.settings.keys`에 바꾼 것만). 같은 키를 고르면 서로 바뀜.
- 창은 누르는 동안 다시 그리지 않음(`Windows.pressing` — 버튼이 사라져 눌림이 없어지던 문제).
- 장비창: 가운데 초상화, 양옆에 부위 칸 5개씩(`equipGrid`, `.doll2`).
- 가이드북 탭(`windows.guide()`): 목차 11개 + 그림 · 설명. 게임 규칙을 바꾸면 여기도 고친다.
- 세로 화면: 게임 전체를 회전 (`src/rotate.js`, eonrift `src/core/rotate.ts`를 본떴다).

## 5. 서버 (eonrift `worker/ashen.ts`, dev 브랜치)

- 라우팅: `worker/index.ts`가 `type`이 `ash_`로 시작하면 `ashen()`으로 넘김. 새 요청 종류를 만들어도 index.ts는 안 고쳐도 된다.
- D1 표: `ash_users`(아이디 · 비밀번호 PBKDF2) · `ash_tokens`(계정당 최근 5개) · `ash_saves`(열쇠 `아이디/cid`) · `ash_saves_prev`(한 시간 넘은 이전 저장 백업) · `ash_active`(계정당 지금 하는 토큰) · `ash_names`(소문자 닉네임 → 캐릭터 열쇠) · `ash_rank` · `ash_errors`.
- 요청: `ash_register` · `ash_login` · `ash_logout` · `ash_save {cid,data,at}` · `ash_load {cid}` · `ash_restore {cid}` · `ash_claim {cid}` · `ash_ping` · `ash_chars` · `ash_nick {cid,nick}` · `ash_delchar {cid}` · `ash_rank` · `ash_err`.
- 저장은 `at`(기기 시각)이 더 새 것만 덮는다 + `ash_active`가 다른 토큰이면 `moved`.
- `ash_chars`를 처음 부르면 예전 단일 저장(열쇠 = 아이디)을 `아이디/c????`로 옮긴다.
- 게임 쪽 주소는 `src/net/cloud.js` `API` (dev 주소). 영겁의 틈새가 출시되면 본 주소로 바꿀 수 있다고 적혀 있다.

## 6. 사용자 성향 · 정해진 방침

- 고치면 **바로 배포**. 짧게 묻지 말고 판단해서 진행하는 편을 좋아함. 「너가 하고 싶은 거 해」처럼 맡기기도 함.
- 그림 품질에 민감: 잘린 에셋 · 같은 모양 반복 · 조잡한 울타리 · 계단을 잘라 만든 「건물」을 싫어함. 건물은 온전한 모양으로, 서로 다르게.
- 튜토리얼 · 안내 문구는 거슬린다고 함 → 없앰. 필요한 설명은 가이드북에.
- 드랍은 아주 짜게(옛날 게임처럼), 강화는 높은 단계가 매우 어렵게(+10 5%) + 장기백.
- 패치노트(`src/data/patchnotes.js` `PATCH_NOTES` 맨 위 + `GAME_VERSION`)는 짧은 안내체 「~했습니다」, 번호 목록. 내부용(통계 · 서버 구조)은 적지 않는다.
- 데이터 일관성(여러 기기)에 신경 씀.

## 8. 남은 일 · 알려진 점

- **강화 +11~+20 · 장비 파괴** (사용자가 「추후에」라고 함).
- 통나무집 띠 이음매가 확대하면 세로 줄로 살짝 보일 수 있음.
- 다른 기기로 넘어갈 때 옛 기기의 마지막 서버 저장 뒤 최대 약 20초 진행은 넘어오지 않음.
- 기능이 없는 예전 버전 화면을 켜 둔 기기는 멈춤 창이 안 뜸(대신 저장이 서버에서 거절돼 덮어쓰지는 않음).
- 접속할 때마다 맵이 바뀌므로 던전 · 먼 지역에서 나가면 다시 마을에서 시작.
- dev-eonrift는 이 컨테이너에서 접속이 안 되므로 실제 서버로 끝까지 시험해 보지는 못했다. 사용자에게 휴대폰 · PC로 직접 확인을 권해 둠.
- 기획 문서(`docs/로드맵.md` · `기획서.md` · `GDD.md`)는 일부 예전 내용. 큰 방향 참고용.

## 9. 서버를 끼고 시험하는 법 (이 컨테이너에서)

```bash
mkdir -p $SCRATCH/srv && cd $SCRATCH/srv
git -C /home/user/eonrift show origin/dev:worker/ashen.ts > ashen.ts
```
- D1 흉내: `node:sqlite`의 `DatabaseSync(':memory:')` + `throttle` 표를 미리 만들고, `prepare(sql).bind(...).first/all/run`, `batch([...])`를 감싼 작은 객체.
- 실행: `node --experimental-strip-types --no-warnings run.ts` (playwright는 `createRequire(import.meta.url)('playwright')`).
- 브라우저 요청 가로채기: `context.route('https://dev-eonrift.weak0416.workers.dev/**', r => r.fulfill({ json: await ashen(db, JSON.parse(r.request().postData()), ip) }))`, GET(`?action=ash`)에는 `{ ash: true }`.
- 이렇게 확인한 것: 두 기기 이어하기 · 옛 기기 멈춤 · 서버 값 보존, 닉네임 중복 거절 · 새 기기에서 서버 캐릭터 목록 · 순위 닉네임.
